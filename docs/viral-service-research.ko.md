# 몇 분 즐기고 친구에게 보내는 서비스 리서치

조사일: 2026-10-29 · 대상: 한국의 친구 관계에서 모바일 링크로 퍼질 수 있는 소규모 웹 서비스

## 결론

첫 실험은 **‘우리 둘 취향 싱크’**를 추천한다. 6개 질문에 답한 사람이 링크를 보내면, 친구는 같은 질문에 답하고 둘이 같았던 선택과 달랐던 선택을 확인한다. 가입 없이 혼자 시작하고, 친구가 나중에 참여해도 완결된다. 결과는 ‘나는 이런 사람’보다 ‘우리 둘은 여기서 통한다’에 초점을 맞춘다.

공유가 일어나려면 짧은 사용 시간 외에 **보낼 명분, 받은 사람의 행동, 그 행동 뒤의 보상**이 있어야 한다. 숫자 기록은 도전, 같은 문제는 대화, 창작물은 구경과 재창작, 관계 비교는 상대방의 참여를 만든다. 이것은 아래 기능을 바탕으로 한 제품 설계 해석이며, 특정 기능이 성장을 일으켰다는 인과관계를 입증한 것은 아니다.

## 조사 범위와 신뢰도

- 직접 확인: 제작자·관리자의 README 및 일부 구현 코드. 출처는 [확인 기록](sources.ko.md)에 파일과 커밋 단위로 남겼다.
- 미실행: 각 서비스의 실제 모바일 플레이, 공유 미리보기, 현재 로그인 조건, 실사용 소요 시간.
- 아래 시간은 본 조사에서 설정한 벤치마킹용 예상 범위다. 측정값이 아니다.
- 이용자 수, 공유율, 매출 및 최신 유행 순위는 확인하지 않았다. 특히 공개 소스가 있다는 사실을 ‘바이럴 성공’의 증거로 취급하지 않는다.
- Wordle·Spotify Wrapped·Neal.fun은 잘 알려진 추가 비교 대상으로 별도 기재했다. 원문 접근이 제한되어 이번 직접 확인 사례와 같은 근거 수준으로 쓰지 않는다.

### 1. 2048: 규칙보다 행동이 먼저

README와 게임 HTML에서 숫자를 합쳐 2048을 만들라는 목표, 점수, 최고 기록, New Game 및 재시작을 확인했다. 조작과 피드백이 즉각적이라 별도 설명 페이지가 필요 없는 구조다. 다만 오래 붙잡는 퍼즐이기도 하므로 ‘몇 분 잠깐’이라는 조건에는 종료 지점이 있는 변형이 더 적절하다.

적용: 결과를 낼 때까지 횟수나 시간을 제한하고, 한 번 더 하기를 공유와 별도로 제공한다. 점수 카드가 있다면 단순 숫자보다 ‘같은 조건에서 해보기’ 링크를 함께 제공한다.

### 2. hello wordl: 결과보다 같은 문제를 전달

README는 6번의 추측과 색 단서를 설명한다. `src/App.tsx`에는 오늘의 시드 선택이 있고, `src/Game.tsx`에는 도전 링크와 결과 공유, `navigator.share` 및 클립보드 경로가 있다. 친구가 같은 도전을 수행할 수 있다는 점과 정답을 바로 드러내지 않는 결과 형식이 벤치마킹 포인트다.

적용: 친구에게 보낸 링크의 질문 세트와 버전을 고정한다. 결과 텍스트만 복사했을 때도 무엇을 하면 되는지 한 문장으로 이해되어야 한다. 공유 API 실패·취소 시에는 사용자가 다시 복사할 수 있게 한다.

### 3. Monkeytype: 기록이 대화의 소재

공식 README에서 속도와 정확도, 여러 테스트 길이, 챌린지, 성과에 따른 Discord 역할을 확인했다. 기록이 개인 만족을 넘어 커뮤니티에서 보여줄 수 있는 표지가 되는 설계다. 공개 자료만으로 실제 공유율이나 역할 기능의 성장 효과를 알 수는 없다.

적용: 수치를 쓴다면 의미와 계산법을 명확히 한다. 비교 모집단이 없는데 ‘상위 1%’를 표시하지 않는다. 모바일이 주 유입이면 타이핑 실력 대신 탭 몇 번으로 완결되는 입력을 택한다.

### 4. Sandspiel: 링크 자체가 작은 작품

제작자는 README에서 창작물을 다른 사람과 공유하고 포크하는 경험을 목표로 적었다. 단순 결과 점수와 달리 받은 사람이 구경할 대상이 있고, 다시 만들 재료가 있다.

적용: 이미지나 조합 결과를 보기 좋게 만들되, 링크를 열어야만 가치가 생기는 구조에 의존하지 않는다. 공유 카드에서도 재미를 주고, 본문에서는 새 결과를 만들 수 있게 한다. 첫 실험에는 자유 창작 도구보다 제한된 선택을 조합하는 방식이 부담이 적다.

### 5. Scribble.rs: 초대가 기능의 일부

공식 README는 계정 없는 그림 맞히기 게임이며 skribbl.io의 대안이라고 설명한다. 로비·연결 관리와 WebSocket 요구가 있어 실시간 친구 놀이가 어떤 운영 복잡도를 가져오는지도 드러난다.

적용: 첫 버전은 비동기로 만든다. 공유한 사람이 자리를 떠나도 받은 친구가 결과까지 도달하게 한다. 실시간 방은 반응이 검증된 뒤 검토한다.

## 공통 설계 원칙

1. **가입 전에 한 번 완결한다.** 유입 후 첫 선택까지 안내를 최소화한다.
2. **받은 친구의 일을 한 문장으로 말한다.** ‘내 결과 보기’보다 ‘너도 6개 골라서 우리 비교하기’가 구체적이다.
3. **공유할 이유를 결과 안에 만든다.** 일치한 취향, 예상 밖 조합, 도전 가능한 기록처럼 대화 소재를 준다.
4. **같은 조건을 보존한다.** 문제·룰 버전이 다르면 결과 비교의 의미가 사라진다.
5. **링크만 받아도 맥락이 보인다.** 카드에 서비스명, 할 일, 예상 시간을 넣는다. 과장된 심리 진단은 하지 않는다.
6. **강제 초대를 쓰지 않는다.** 결과를 보려면 친구 N명에게 보내라는 방식은 첫 실험에서 제외한다.
7. **짧게 끝나도록 설계한다.** 무한 재시도나 무한 스크롤 대신 6문항과 한 장 결과를 기본으로 삼는다.

## 후보 선택

점수는 조사자의 제품 판단이며 사용자 실험 결과가 아니다. 5점이 유리하며 ‘구현 용이성’은 높은 점수가 단순함을 뜻한다. 가중치는 두지 않았다.
