# 클라우드 환경 사용법

확인일: 2026-10-29

## 현재 준비된 작업

`/workspace/viral`은 문서 리서치·기획 저장소다. 문서는 GitHub에서 읽으며 설치, 실행 서버, 외부 서비스, DB, API 키가 필요하지 않다. 아직 서비스 코드를 구현하거나 배포하지 않았다.

기존 클라우드 체크아웃을 그대로 사용한다. 각 작업은 이미 격리되어 있으므로 사용자가 명시적으로 요청하지 않는 한 별도 Git worktree를 만들지 않는다.

## 도구와 네트워크

- 현재 인스턴스에서 Git 2.52.0, Node.js 24.19.0, npm 11.9.0, Python 3.12.14를 확인했다. 앱의 버전 핀을 지정한 것은 아니다.
- GitHub 인증은 플랫폼 HTTPS Git 프록시를 사용한다. 토큰을 파일에 넣거나 로그에 출력하지 않는다.
- 네트워크는 제한 모드이며 패키지 관리자 프리셋을 사용한다. GitHub 및 raw.githubusercontent.com의 필요한 읽기를 확인했다.
- NYT, Neal.fun, Pudding, Spotify Newsroom 등으로의 요청은 프록시 403으로 제한되었다. 이를 해당 서비스의 장애나 인증 실패로 해석하지 않는다.
- 원문 후속 조사가 필요하면 환경 설정에 필요한 도메인만 추가한다. 이번 문서 작업에는 추가 비밀값이나 네트워크 정책 변경이 필요하지 않았다.

## 시작과 검증

```sh
cd /workspace/viral
git status --short
git ls-files
git ls-remote origin refs/heads/main
```

문서를 수정할 때는 내부 상대 링크의 대상이 존재하는지 확인하고, 관찰한 사실·제품 해석·아직 검증하지 않은 가설을 구분한다. 설치·빌드·테스트 명령은 아직 없으며 문서 검증을 애플리케이션 테스트 통과로 표현하지 않는다.

## 다음 개발 작업

사용자가 서비스 구현을 요청하면 [MVP 제안](mvp-proposal.ko.md)을 출발점으로 질문·공유·비교 흐름을 만든다. 그때 선택한 기술 스택의 lockfile과 실제 빌드·테스트 명령을 추가하고 설치 및 시작 설정을 갱신한다. 라이브 프로세스는 클라우드 스냅샷에 유지된다고 가정하지 않는다.

## 설정 저장과 게시

환경 초안에는 실제 체크아웃 위치·커밋과 문서 작업 시작 안내를 저장한다. 의존성이 없으므로 설치 스크립트는 만들지 않는다. 초안 저장은 현재 머신에 명령을 실행하거나 환경을 게시하는 동작이 아니다. 설정 검토·저장 및 Publish는 환경 UI에서 사용자가 진행한다. 새 작업의 스냅샷 복원은 별도 확인이 필요하다.
